# Copilot Harness v0.3.0 — Policy Gate & Verification Runtime

v0.3.0 adds the reliability layer that turns harness policy and verification guidance into executable Windows-first behavior.

## Highlights

- A0-A4 Policy Gate contract for action authorization boundaries.
- `scripts/policy-check.ps1` for deterministic policy decisions.
- V0-V4 Verification Contract for engineering evidence requirements.
- `scripts/verify.ps1` for deterministic verification states and exit codes.
- Copilot instructions wired to policy and verification contracts.
- Installer, manifest and doctor integration for the new runtime assets.
- Windows smoke coverage for policy and verification behavior.
- Optional GitHub Spec Kit extension strategy for `bug`, `git`, `assess`, and `agent-context`.

## Reliability model

```text
Spec Kit scope
    -> Copilot proposal
    -> Policy Gate
    -> approved execution
    -> Verification Contract
    -> PASS / FAIL / BLOCKED / SKIPPED / NOT RUN
    -> accept or feed evidence back into implementation
```

The core rule is simple: model output is not execution evidence. A successful result requires actual deterministic evidence from the relevant verification path.

## Policy decisions

The runtime distinguishes:

- A0: read-only/reasoning;
- A1: local reversible verification;
- A2: repository mutation within requested scope;
- A3: remote/shared-state mutation requiring explicit intent or an approved workflow;
- A4: destructive, production or security-sensitive actions requiring immediate explicit approval.

## Verification evidence

The runtime preserves five evidence states exactly:

- `PASS`
- `FAIL`
- `BLOCKED`
- `SKIPPED`
- `NOT RUN`

Only `PASS` is passing evidence.

## Spec Kit extensions

Official Spec Kit extensions can accelerate parts of the workflow, but do not become hidden authorization or verification dependencies:

- `bug` supports assess/fix/test defect workflows;
- `git` supports branch workflow/validation;
- `assess` supports pre-SDD idea assessment;
- `agent-context` can optionally help synchronize agent context.

The Policy Gate remains the authorization boundary and the Verification Contract remains the acceptance/evidence boundary.
