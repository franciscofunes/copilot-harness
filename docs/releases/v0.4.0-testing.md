# v0.4.0 Release Testing — Repository Verification Profiles

Evidence states follow `docs/RELEASE-TESTING.md`: `PASS`, `FAIL`, `BLOCKED`, `SKIPPED`, `NOT RUN`. Only actual successful execution may be marked `PASS`.

## Scope

This release adds repository-owned verification profiles, direct process execution, command allowlisting, policy-class restrictions, change-type filtering, and repository-neutral branch guidance.

## Mandatory gate

Do not promote `release/0.4.0` to `main` with any `FAIL` result.

V040-001 through V040-022 must be resolved before promotion. A scenario may become `SKIPPED` only when it is genuinely not applicable and the reason is documented. `BLOCKED` requires an explicit risk decision. `NOT RUN` is never passing evidence.

## Release-specific risk focus

The highest-risk regression in this release is treating repository-controlled profile content as authorization. Tests must prove that a profile can select deterministic local verification but cannot grant itself A2, A3, or A4 permission.

A second risk is branch-policy leakage: this harness repository's internal branching topology must not be emitted as a requirement for installed target repositories.
