## Known review risks and limits

- GitHub Actions are now pinned to verified first-party v4 commit SHAs: [checkout `11d5960a` ](https://github.com/actions/checkout/commit/11d5960a326750d5838078e36cf38b85af677262) and [upload-artifact `ea165f8d`](https://github.com/actions/upload-artifact/commit/ea165f8d65b6e75b540449e92b4886f43607fa02). The official v4 tags were resolved on 2026-11-08. This removes tag drift but does not substitute for reviewing upstream code or considering a future major-version upgrade. CI runtime deprecation notices, if any, require explicit review.
- A bounded regex check cannot establish that the repository has no secrets. It does not scan history, files outside its allowlist, binary content, or external systems.
- The Git-blob SHA-1 inventory is only a **pristine-file compatibility detector**. It is not a signature or cryptographic provenance attestation of upstream downloads.
- CI uses disposable Windows fixtures and skips optional external tool bootstraps; it does not prove Spec Kit or CodeGraph installation on a real user device.
- The manual VS Code / Visual Studio acceptance gate Q-07 is independent of these checks and remains blocked until observed evidence is provided.
- A green CI run on this review PR is provisional. After any changes are merged, re-run at the resulting exact `release/1.2.0` SHA.
