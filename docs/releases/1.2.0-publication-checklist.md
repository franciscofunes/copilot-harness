**Description:**

> ## Copilot Harness v1.2.0
>
> This release adds repository-native advisory skills for **SQL Server**, **MongoDB**, and **Snowflake**, including stack-aware selection checks and Doctor diagnostics. It also introduces an opt-in, fail-closed **managed upgrade from the published v1.1.0 baseline**, with SHA-256 backup evidence and targeted rollback.
>
> ### What's new
> - SQL Server, MongoDB and Snowflake Copilot review skills.
> - Selection benchmarks for positive, negative and mixed-stack cases. The static character-footprint comparison does **not** measure actual LLM token usage or cost.
> - Installer and Doctor improvements for managed content and optional skill diagnostics.
> - Opt-in `-ConflictMode managed-upgrade` that refuses customized managed files before changing them, plus recoverable backup/rollback.
>
> ### Important upgrade behavior
> - The default `skip` mode preserves modified content, may yield a `PARTIAL` upgrade and does **not** claim that outdated runtime files became 1.2.0.
> - `managed-upgrade` supports pristine v1.1.0-managed files; modified managed files require human review/rebase. Optional external bootstraps are excluded from this transactional path.
> - Back up real repositories separately and review all changed files before attempting upgrades.
>
> ### Known limitation — live Copilot IDE acceptance not performed
> **All four native-skill adoption scenarios in real VS Code and Visual Studio remain unobserved (0/4).** Deterministic installer and skill checks have run, but they are **not proof of skill discovery or invocation in those IDEs**. These tests are deferred to [Issue #90](https://github.com/franciscofunes/copilot-harness/issues/90). Publication with this limitation requires a recorded, explicit release-owner risk exception and is not an implicit PASS.
>
> The policy checker classifies action risk; independent Copilot tool execution is not automatically intercepted by the harness. Do not treat the harness as a general Copilot tool-execution firewall.
