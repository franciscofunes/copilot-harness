# Copilot Harness v0.1.0 — Foundation

## Purpose

`v0.1.0` establishes the first stable foundation of Copilot Harness: a Windows-first reliability layer around GitHub Copilot and GitHub Spec Kit for development and QA teams working in Visual Studio and VS Code.

## Included

- GitHub Spec Kit is the authoritative SDD engine.
- Windows + PowerShell are the canonical workstation baseline.
- VS Code uses Spec Kit's native Copilot integration where available.
- Visual Studio uses shared repository instructions and prompt files against the same versioned Spec Kit artifacts.
- Repository-wide Copilot instructions remain intentionally small to reduce repeated context/token usage.
- Path-scoped instructions exist for .NET / ASP.NET Core, Angular / TypeScript, data workloads, and tests / QA.
- Harness engineering is defined as a reliability loop: context builder → reasoning → policy gate → tools/runtime → verification → accepted result.
- Git Flow, Semantic Versioning, QA traceability, and mandatory Mermaid PR diagrams are established.

## Supported engineering landscape

The foundation is designed around .NET / ASP.NET Core, Angular, SQL Server, MongoDB, Snowflake, Parquet, Azure DevOps, GitHub, and JFrog.

## Explicit constraints

- No MCP server is required by the company baseline.
- No marketplace plugin is required by the company baseline.
- Approved CLIs and repository-local files/scripts are the deterministic execution surface.
- AI output alone is not verification evidence.

## Status

This is a foundation release rather than the final end-user bootstrap experience. A developer can inspect and adopt the conventions, but the one-command Windows installer and automated health checks are not yet included.

## Next milestone — v0.2.0

Planned focus:

4. `doctor.ps1` health checks.

## Upgrade

There is no prior released version to migrate from. This is the initial release baseline.
