# v1.2.0 Q-08 — Security and provenance review

**State: NOT RUN / NOT SIGNED.** This runbook distinguishes automated clues from decisions a named security reviewer and release owner must make. No scanner output alone authorizes a v1.2.0 tag or publication.

## Automated bounded checks

1. On the exact candidate commit, the existing tests/release-1-2-provenance-smoke.ps1 checks selected HEAD files for high-confidence secret patterns, release metadata, baseline fingerprints, and workflow permissions/action pins.
2. The new scripts/audit-release-history-secrets.ps1 examines **added lines in Git text-patch history** reachable from the candidate HEAD. This catches a high-confidence credential marker added in an earlier commit even if the file is removed at the current HEAD.
3. The scanner rejects shallow clones, writes a JSON receipt with commit/path/rule identifiers and counts, **never a matched token or source line**, and fails the check if it finds possible secrets. A redacted artifact is uploaded in CI along with the bounded provenance receipt.
4. CI uses a synthetic disposable repository with a token-shaped fixture that is added and later removed. The fixture verifies both detection and redaction. This is not a real credential or a signed security assessment.

For a separate human review of all **locally reachable** branches/tags, on a trusted checkout:

```powershell
git fetch --all --tags
git switch release/1.2.0
git pull --ff-only origin release/1.2.0
$receipt = Join-Path $env:TEMP "v1-2-history-security.json"
pwsh ./scripts/audit-release-history-secrets.ps1 -IncludeAllRefs -ReceiptPath $receipt
```

The command is read-only apart from the reviewer-local JSON receipt; do not commit credentials or raw source. A match means **review required**, not confirmed active exposure. Handle any real incident privately, rotate/revoke affected credentials, and document disposition without quoting secrets.

## Required independent review

- **Exact scope and authorizations:** reconcile Q-01 inventory with the final candidate SHA; inspect executable installer changes, scripts, native skills and tests.
- **Workflow trust:** verify minimal contents-read permissions, trigger scopes, pin identities, complete history checkout requirement, fork PR behavior, and absence of privilege escalation or unsafe execution of untrusted PR content.
- **Secrets and history:** run organization-approved scanning over the full repository and relevant historical refs; investigate findings. The built-in scanner is limited to Git patch text lines and three high-confidence pattern families. It does not scan binary payloads, untracked files, remote services, unreachable objects or validate whether credentials work.
- **Dependencies and remote execution:** inspect optional Spec Kit, CodeGraph and other external bootstrap sources, network trust, downloaded versions, artifact verification, and the behavior of installer upgrades.
- **Release provenance:** ensure v1.1.0 published SHA, v1.2.0 candidate SHA, version/changelog, CI run IDs and evidence receipts refer to the intended scope. Consider whether signed tags, attestations or checksums are required.
- **Risk and owner approvals:** record reviewer name/date, findings and remediation, residual risk, the Q-09 customization-conflict decision, and an explicit owner approval or NO-GO.

Record the final, reviewed evidence and decision in [the Q-08 worksheet](1.2.0-security-provenance.md) and [qualification gate table](1.2.0-testing.md). An automated green run is **not** Q-08 PASS. Q-07 live IDE acceptance and Q-09 policy approval remain independent, and Q-11 remains **NO-GO**.
