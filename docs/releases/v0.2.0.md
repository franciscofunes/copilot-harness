# Copilot Harness v0.2.0 — Bootstrap & Doctor

`v0.2.0` turns the harness foundation into an executable Windows-first adoption workflow.

## Highlights

- Windows bootstrap through `installer/install.ps1`.
- Stack-aware Copilot customization for .NET, Angular, data, and test/QA scenarios.
- Repository detection for .NET, Angular, SQL Server, MongoDB, Snowflake, Parquet, Azure DevOps, GitHub Actions, and JFrog signals.
- Harness diagnostics through `installer/doctor.ps1`.
- Official `https://github.com/github/spec-kit` as the supported SDD engine.
- Explicit Spec Kit Copilot layout selection: `commands` (default) or `skills`.
- Default Spec Kit extension baseline: `git`, `bug`, `assess`.
- `.copilot-harness.json` installation manifest.
- Release testing contract with explicit evidence states and a versioned `v0.2.0` test plan.
- PowerShell smoke checks plus a Windows GitHub Actions smoke workflow.

## Developer flow

```powershell
.\installer\install.ps1 -TargetPath C:\src\my-application
.\installer\doctor.ps1 -TargetPath C:\src\my-application
```

## Spec Kit baseline

The default harness behavior is equivalent to:

```powershell
specify init . --here --integration copilot --integration-options=--commands --force
specify extension add git
specify extension add bug
specify extension add assess
```

Repositories may explicitly opt into the `skills` layout where appropriate.

## Release verification model

Release readiness is evidence-based. The harness recognizes:

- `PASS`
- `FAIL`
- `BLOCKED`
- `SKIPPED`
- `NOT RUN`

Unexecuted checks are never treated as successful. See `docs/RELEASE-TESTING.md` and `docs/releases/v0.2.0-testing.md` for the verification contract and release-specific plan.

## Scope notes

This release focuses on bootstrap, environment discovery, Spec Kit configuration, stack-aware instruction installation, diagnostics, and release evidence. Policy-gate enforcement, application-change verification contracts, branch/ruleset enforcement, semantic upgrades of customized harness files, and a full representative reference application remain follow-up work.
