# v1.2.0 Release Qualification Plan

**Status:** CANDIDATE — NOT RELEASED. **Baseline:** v1.1.0 on `main`. **Candidate source:** `develop`. **Proposed release branch:** `release/1.2.0`.

## Proposed scope

- Native SQL Server review skill: queries, transactions, indexing and safe migrations.
- Native MongoDB review skill: schema modeling, aggregation, indexes and consistency.
- Native Snowflake review skill: SQL transformations, ingestion, permissions and cost-aware diagnostics.
- Conflict-safe installer integration and deterministic skill contract checks.
- Positive, negative and mixed-stack skill-selection benchmark, with **character-count context proxy only**, not measured token savings.
- Stack-aware Doctor diagnostics that treat missing optional native skills as nonblocking WARN.

## Required qualification gates

| Gate | Required evidence | State |
| --- | --- | --- |
| Review `main...develop` comparison and intended change set | Reviewed diff, commit SHAs and reviewer | NOT RUN |
| PowerShell and JSON syntax, deterministic Harness Smoke | Workflow run URL, SHA, conclusion | NOT RUN |
| Fresh install and upgrade preservation | Install/upgrade smoke and evidence | NOT RUN |
| Native data skill installation, contracts and selector cases | Native skill smoke and eight selector cases | NOT RUN |
| Doctor readiness and advisory skill diagnostics | Doctor smoke, PASS/WARN and fail-closed negative path | NOT RUN |
| Real VS Code and Visual Studio skill invocation | Redacted IDE acceptance records and exact versions | BLOCKED |
| Review secrets, provenance, changelog and documentation | Reviewer checklist and references | NOT RUN |
| Release branch CI on final release head | Workflow URL, SHA, green conclusion | NOT RUN |
| Upgrade from v1.1.0 and rollback review | Disposable repo results and restoration procedure | NOT RUN |

**Evidence states:** PASS, FAIL, BLOCKED, SKIPPED, NOT RUN. Never mark a gate PASS based solely on creating a plan. Live IDE evidence can only be deferred with explicit reviewer approval and a clear release-note limitation.

## Release procedure

1. Merge this planning PR into `develop` only after CI passes.
2. Freeze intended scope; review `main...develop` and collect required automated and manual evidence.
3. Create `release/1.2.0` from `develop`. Update `VERSION` to `1.2.0` and draft `CHANGELOG.md` on the release branch.
4. Open release candidate PR targeting `main`. Run release-head CI, verify upgrade/rollback, and record review approvals.
5. Merge only when mandatory gates pass and any IDE evidence deferral is explicitly accepted.
6. Tag `v1.2.0` on the final `main` commit, publish release notes, then merge `main` back into `develop`.

## Rollback and compatibility

Keep v1.1.0 as the baseline. Default installer conflict mode must preserve repository-owned files. If qualification fails, do not promote; fix the release branch and rerun checks. For installed repositories, restore backups and reinstall the pinned known-good release after validation. No production rollback is claimed as tested until evidence exists.

## Version rationale

A minor version is proposed for additive advisory skills, benchmarks and Doctor diagnostics. If validation discovers a breaking catalog or installer change, reassess versioning before publication.

**Principle:** Copilot proposes; the harness verifies.
